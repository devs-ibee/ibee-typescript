# IBEE Solutions TypeScript SDK

TypeScript / JavaScript client for the IBEE Solutions public API: compute,
VPC networking, Reserved IPs, firewalls, load balancers, object and block
storage, CDN, Secret Store and Container Registry.
Node 18+ (ESM and CommonJS) and modern browsers.

The client is generated by [Fern](https://buildwithfern.com) from the IBEE API
contract (OpenAPI 0.6.2). It sends your request and hands back the server's
answer unchanged. A small hand-written layer adds configuration, safe retries,
automatic idempotency keys and error fields (`src/wrapper/`).

## Install

```bash
npm install ibee-sdk
```

## Authenticate and configure

```ts
import { Ibee, IbeeEnvironment } from "ibee-sdk";

const ibee = new Ibee({
    token: "ibee_prod_key_...", // or set IBEE_API_TOKEN
    workspaceId: "710995", // default workspace_id for every call, or IBEE_WORKSPACE_ID
    environment: IbeeEnvironment.Production, // or IbeeEnvironment.Development, "prod", "dev", or IBEE_ENV
});
```

| Option | Environment variable | Default |
| --- | --- | --- |
| `token` | `IBEE_API_TOKEN` (or `IBEE_TOKEN`) | required |
| `workspaceId` | `IBEE_WORKSPACE_ID` | none; pass `workspace_id` per call |
| `environment` | `IBEE_ENV` (`prod` / `dev`) | production, `https://api.ibee.ai/v1` |
| `baseUrl` | `IBEE_API_URL` | overrides `environment`; https only (http for localhost) |
| `timeoutInSeconds` | | 60 |
| `maxRetries` | | 2 |
| `fetch` | | global `fetch` |

Options you pass win over environment variables. Production tokens start with
`ibee_prod_key_` and development tokens with `ibee_dev_key_`; the client refuses
a token on the other environment's gateway. A `workspace_id` in a call
overrides the default.

## Example

Method and field names follow the API contract (`operationId` and the JSON
field names), so the [API reference](https://docs.ibee.ai) maps one to one.

```ts
const { sites } = await ibee.computeCatalog.listComputeSites();
const { plans } = await ibee.computeCatalog.listComputePlans({ vm_type: "cloud", site_id: sites[0].site_id });
const plan = plans[0];

const operation = await ibee.cloudVms.createCloudVm({
    name: "web-01",
    site_id: plan.site_id ?? sites[0].site_id,
    plan_id: plan.plan_id,
    template_id: "tmpl_ubuntu_2204",
    os_type: "linux",
    os_distro: "ubuntu",
    cpu: plan.cpu,
    ram_mb: plan.ram_mb,
    ssh_key_ids: ["key_123"],
    billing_term: "HOURLY", // or "MONTHLY" (a one-month commitment); HOURLY when omitted
});

const status = await ibee.cloudVms.getComputeOperation({ operation_id: operation.operation_id });
```

`billing_catalog` on VM create is the contract's `ComputeBillingSelection`: a copy
of the plan's `billing_catalog` with one of its `billing_options` entries
(`HOURLY` or `MONTHLY`) merged in whole. Leave it out and the SDK builds it from
the plan for `billing_term` (see [Temporary client-side behaviour](#temporary-client-side-behaviour)),
or pass the plan's `billing_catalog` with `billing_term`. The server checks the
selection: no term is 400 `compute_billing_term_required`, a partial or
mismatching one 400 `invalid_compute_billing_selection`. A `MONTHLY` VM cannot be
deleted or resized during its commitment (409 `VM_COMMITTED`).

Resize takes the target shape: `resizeCloudVm({ vm_id, body: { cpu, ram_mb, disk_gb } })`
(`precheckCloudVmResize` first if you want the decision).

Every method returns the parsed response body. Use `.withRawResponse()` for the
headers too:

```ts
const { data, rawResponse } = await ibee.cloudVms.getCloudVm({ vm_id: "..." }).withRawResponse();
console.log(rawResponse.headers.get("x-request-id"));
```

### Container Registry

```ts
const registry = await ibee.containerRegistry.createContainerRegistry({
    registry_name: "acme-apps",
    confirm_registry_name: "acme-apps",
    billing_catalog: { sku_code: "REGISTRY-STORAGE-250GB" },
});
// 202 while provisioning: poll getContainerRegistry until observed_state is "ACTIVE".

const token = await ibee.containerRegistry.createContainerRegistryAccessToken({
    registry_id: registry.registry_id,
    token_name: "ci-push",
    permission: "PULL_PUSH",
});
// token.username and token.secret are returned once (docker login registry.ibee.ai).
```

The registry service (and Billing, which it asks) answers; the SDK sends the
request as given.

### Object storage settings

Bucket lifecycle, CORS, object lock, notifications, custom domains and metrics
are REST operations on `ibee.objectStorage` (`getBucketCors` / `setBucketCors` /
`deleteBucketCors`, and so on). Answers come back as the server sends them: the
CORS read currently uses S3 casing (`AllowedOrigins`, ...) while the write takes
snake_case; object lock is chosen at bucket create and cannot be turned off;
adding a custom domain answers 400 until the hostname CNAMEs to `cname_target`.
S3 keys: `revokeS3Credential` revokes (`POST .../revoke`), `deleteS3Credential`
deletes; `permission_type` is `admin_rw` (default), `admin_ro`, `object_rw` or
`object_ro`. Snapshot and backup SKUs come from
`computeCatalog.listSnapshotStoragePlans` / `listBackupStoragePlans`.

Per-call options go in the second argument: `{ timeoutInSeconds, maxRetries,
abortSignal, headers, queryParams }`.

## Errors

Every API error is an `IbeeError` (or a subclass per status, such as
`PaymentRequiredError`, `ForbiddenError`, `ConflictError`, `LockedError`). The
SDK adds no wording of its own; it exposes what the server sent:

```ts
import { IbeeError } from "ibee-sdk";

try {
    await ibee.cloudVms.createCloudVm(request);
} catch (err) {
    if (err instanceof IbeeError) {
        err.statusCode; // 402
        err.code; // the body's `error` (or `code`), e.g. "billing_denied"
        err.billingReason; // `billing_reason`, e.g. "insufficient_balance"
        err.admissionContextId; // `admission_context_id`
        err.serverMessage; // the server's `message` / `detail`, when present
        err.requestId; // the `x-request-id` header
        err.body; // the whole response body, as sent
    }
    throw err;
}
```

The fields are read from the top level of the body, then from `detail`, then
from `error` when those are objects. Timeouts throw `IbeeTimeoutError`.

## Retries

A request is retried (up to `maxRetries`, default 2) only when repeating it is
safe and the answer is temporary:

- **What:** GET and HEAD, and writes that carry an idempotency key
  (`X-Idempotency-Key`, `Idempotency-Key`, or `idempotency_key` in the body
  or query). VM create
  is not retried. The Secret Store identity access read is never retried,
  because each call issues a new secret ID.
- **When:** only on 429 and 503, and only if the body has no billing or
  admission answer (`billing_reason`, `admission_context_id`, or a code
  mentioning billing, admission, catalog or quote). 502, 504 and other
  statuses are never retried.
- **Delay:** `Retry-After` (capped at 30 s), otherwise 1 s, 2 s, ... with
  jitter.

The contract requires `X-Idempotency-Key` on the 18 VM write operations, and
`Idempotency-Key` on Container Registry plan upgrade
(`upgradeContainerRegistryPackage`). When you do not pass one, the SDK sends a
random key. Pass your own key to retry a write safely across processes.

## Temporary client-side behaviour

Until the server resolves these itself, `src/wrapper/held.ts` keeps what 0.4.x
did:

- `createCloudVm` / `createGpuVm` without `billing_catalog`: the plan's
  `billing_catalog` (`GET /compute/plans`) is copied and its `billing_options`
  entry for `billing_term` (`HOURLY` or `MONTHLY`; `HOURLY` when omitted) is
  merged into the copy as a whole (`billing_interval`, `committed`,
  `commitment_period`, `commitment_months`, `committed_hours`, `price_unit`,
  `unit_price_minor`), keeping `price_currency`. A given `billing_catalog`
  without `billing_interval` is merged the same way; one with
  `billing_interval` is sent as given unless you pass `billing_term`. A term
  the plan does not offer leaves the copy unchanged and the server answers.
  `windows_license` and the Reserved IP SKU of `reserved_public_ip_id` go into
  `attached_skus`.
- `deleteCloudVm` / `deleteGpuVm`: the `body` may be omitted. Nothing is added
  to it: for a VM with an automatically assigned public IP the server answers
  400 until you pass `public_ip_action` `release` or `reserve`.
- `attachCloudVmVolume` / `attachGpuVmVolume` without `billing_catalog`: the
  volume's `metadata.billing_catalog` (left out when the volume has none, and
  the server answers).
- `disableCloudVmBackups` / `disableGpuVmBackups` send the JSON body `{}`: the
  contract declares no body, and the server answers 422 without one.
- `createVpc` accepts `nat_billing_catalog`, `createNatGateway` accepts
  `billing_catalog` (NAT metering).
- `listCloudVms`, `listGpuVms` and `listFirewallGroups` read every page when
  you pass neither `limit` nor `offset` (the server returns 10 by default).

## Regenerating

`src/` is Fern output from `contract/ibee-cloud.yaml` (an exact copy of
`fern/openapi/ibee-cloud.yaml` in platform-docs) with the settings in `fern/`,
except the files listed in `src/.fernignore`. To regenerate (Fern CLI 5.45.3
and Docker):

```bash
scripts/regenerate.sh
npm run typecheck && npm run build && npm test
```

`fern/overrides.yml` makes `workspace_id`, `X-Idempotency-Key` and
`Idempotency-Key` optional in the generated types, because the client fills
them.

CI checks every pull request:

- `scripts/check-generated.sh`: regenerating from `contract/ibee-cloud.yaml`
  gives the committed `src/` (the hand-written files aside).
- `scripts/check-contract-calls.mjs`: the hand-written files call only
  operations and paths of `contract/ibee-cloud.yaml`.

A pull request that changes `contract/**` gets the regenerated code pushed to
its branch (`.github/workflows/regenerate.yml`).
